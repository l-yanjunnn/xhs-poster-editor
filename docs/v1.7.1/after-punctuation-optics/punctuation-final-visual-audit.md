# V1.7.1 标点最终视觉 / 几何复核

复核日期：2026-08-12（北京时间）

范围：`minimal-p01`、`minimal-p02` 的 1080×1800 预览、2160×3600 导出和对应 layout JSON。当前快照分别为 p01 `85a43558`、p02 `27ac5283`。

## 结论

- 用户指出的双引号、冒号、顿号已改为实际墨迹双侧净空模型，不再用 `glyphOffset = 0` 或“只压后侧”代替视觉判断。
- 双引号不再只保一侧：内侧首选 0.18em（硬下限 0.14em），外侧首选 0.22em（硬下限 0.16em）；旧版约 0.05–0.09em 的贴字已消失。
- p02 普通文字夹冒号的左右最大差为 0；顿号、逗号的文字前距硬下限已提高至 0.15em，不会在极端行宽下再被压到 0.12em。
- `。”`、`”，`、`：“`、`”“` 等连续标点共享一次 boundary，不叠加两份边距，也不在 cluster 内断行。
- p02 列表继续使用自然句末和自然断行，旧证据中为了卡行宽而添加的列表行末分号不再存在。新增的「行末悬挂专测」是独立回归样例，不是为了伪造列表换行。
- 行末闭标点允许非零 `glyphOffset` 以维持合适的入侧净空；宽度、字形原点和可见右缘由同一个连续求解联合收敛，`。”` 连续标点在极端行宽下也不会反弹错位。`visibleRightError = 0`。
- p01/p02 的预览与导出肉眼一致；全局比较的水平/垂直 lag 均为 0，墨迹边界最大差 1 CSS px。
- 所有两端对齐行的求解器 `right - target` 误差为 0，汉—汉字缝同行最大偏差为 0，混排 baseline spread 为 0。
- 没有发现会阻断本轮用户验收的视觉问题。

## 关键标点几何（CSS px）

`left gap` / `right gap` 均按相邻字形实际墨迹边缘计算，而不是元素框。它们各自有字符级硬下限、首选值和上限，求解器可在区间内同时移动逻辑框宽与字形原点。`em` 为该标点字号。

| 页面与文本 | box/em | glyphOffset | left gap | right gap | 判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| p01 `种“归` | 动态 | 动态 | `种→“` 0.220em | `“→归` 0.180em | 开引号外侧有呼吸、内侧不贴字 |
| p01 `纳”陷` | 动态 | 动态 | `纳→”` 0.180em | `”→陷` 0.220em | 闭引号内外侧协调 |
| p01 极端压缩引号 | 动态 | 动态 | 内侧最低 0.140em | 外侧最低 0.164em | 两侧都不越硬下限 |
| p02 `字“引号”后字` | 动态 | 动态 | 内侧 0.180em | 外侧 0.220em | 双引号四边专项通过 |
| p02 普通文字夹 `：` | 动态 | 动态 | profile 内 | profile 内 | 左右最大差 0em |
| p02 `。”` / `”，` / `：“` | 动态 | 动态 | — | cluster 0.08–0.16em | 共享净空通过 |

p02 的 `06e705a6 / line 0` 以「行末悬挂专测：汉字与标点前距自然；」结行。布局数据的求解器坐标如下：

| 项目 | 值 | 验证 |
| --- | ---: | --- |

| 分号 `glyphOffset` | 0.56px | 双侧模型按实际墨迹移动字形原点 |
| 入侧可见净空 | 8.00px / 0.20em | `strong-leading` profile 通过 |
| 分号可见右端 | 674.00px | `visibleRightError = 0` |

## 残余风险（不阻断本轮验收）

1. 双侧 profile 当前以 Noto/思源中文为主要实测字体；未来新增字形重心差异很大的用户字体时，应继续由同一墨迹门禁验证，而不是复用某个固定 box 宽度。
2. 标点的逻辑 box 可因 compact cluster 低于 0.5em，破折号/省略号也可因实际墨迹略高于 1em；视觉安全由“box 完整覆盖墨迹 + 相邻可见净空区间”共同保证，不能再单独用 box/em 判断。
3. 行首开引号的内侧与行末闭引号的入侧/可见右缘均有门禁；段落末行本来不应强制贴右，因此没有把“闭引号到行框右边”设为绝对对齐项。引号邻接用户显式空格时保留该空格语义，不另做墨迹压缩。
